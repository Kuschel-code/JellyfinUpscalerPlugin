Auto Model Selection

On by default. The plugin calls /Upscaler/recommend-model and decides per video from four inputs: content type (genre), source resolution, whether multi-frame models are loaded, and the hardware class the AI service reports. The decision always comes back with the reason, shown on the dashboard, in the player's Auto tab, and in the library-scan log.

What it picks, before the hardware cap is applied:

SourceModelScale
Already 4K or largerdejpg-realplksr-1x / denoise-realplksr-1x1× — cleaned up, not enlarged
Anime, batch, SDrealesrgan-animevideo-x44×
Anime, batch, 720p/1080papisr-anime-x22×
Anime, real timeanime-compact-x44×
Live action, batch, very low resultrasharp-v2-x44×
Live action, batch, SDrealesrgan-x44×
Live action, batch, 720p/1080prealesrgan-x2-plus2× — 4× here would target 8K
Live action, real timespan-x2 / nomosuni-compact-x22×
Multi-frame models loaded, batchedvr-m-x4 / realbasicvsr-x4 / animesr-v2-x44×

Then two filters run over that choice:

  • Hardware budget — models are banded Light / Medium / Heavy and matched against the service's tier (strong-gpu, mid-gpu, igpu, strong-cpu, weak-cpu). An over-budget pick is replaced by the best affordable one and reported: "realesrgan-x4 suits the material but is too heavy for this weak CPU (no GPU) …". An unknown tier caps nothing — auto never blocks on an unreachable service.
  • Scale ceiling — the substitute must not overshoot the target factor. If nothing satisfies both limits, the smallest available overshoot wins, and it is always reported, never silent.

A value in Preferred Anime Model or Preferred Live-Action Model is treated as a deliberate override: it is exempt from both filters and only annotated when it is heavy for your hardware. The colour-filter preset is chosen separately and is a suggestion — auto never overwrites a preset you picked.

The filter suggestion

Auto never applies a colour filter. Until v1.8.3.20 it wrote its own choice into your config whenever the field was empty, so the first playback quietly decided your look and the setting then read back as if you had picked it. A model swap is a correction you cannot make better yourself; a filter is taste.

The player's Auto tab and the sidebar now show “Suggested look (Anime content): vivid” with an Apply button, and only when the suggestion differs from your current preset. Applying goes through the same save path as a manual pick.

AI Models tab

Live model catalog pulled from /models. Each row shows:

  • Status dot - available / downloaded / loaded / unavailable
  • Scale factor - 2×, 3×, 4×
  • VRAM estimate - based on benchmark
  • Actions - Download, Load/Unload, Benchmark

Filter bar: search-by-name + status filter (all / available / downloaded / loaded / unavailable). See the model catalog for the full list.

Filters tab

15 camera-style presets that can be applied either as live CSS overlay (no re-transcode, 60fps) or as server-side FFmpeg filter chain (persists in the output file).

  • Cinematic · vintage film look

  • Vivid · saturated + contrast boost
  • Sepia · monochrome warm
  • Cyberpunk · neon teal/magenta
  • Teal & Orange · Hollywood colour-grade
  • Drama · high contrast desaturate
  • Soft Glow · bloom on highlights
  • Sharp HD · edge enhance + clarity
  • Retro Game · slight scanline
  • Pastel · low saturation pastel
  • Noir · grayscale high-contrast
  • Night Vision · green-channel
  • Thermal · false-colour
  • Custom · 6 FFmpeg params exposed

Hardware tab

Read-only view of what the AI service detected on the container host - useful for debugging why a model isn't loading.

  • Execution providers (CUDA / OpenVINO / DirectML / ROCm / CPU) with version strings
  • GPU list with VRAM, driver, CUDA/compute capability
  • Last benchmark timestamp + FPS per model
  • Onnxruntime version + build flags
